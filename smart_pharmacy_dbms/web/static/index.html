DBMS Architecture & Viva Defense Reference

Gauransh Purohit | Technical explanation for Professor & Evaluators

1. Schema Normalization 3NF & BCNF Decomposition Proof

Every non-prime attribute in medicine depends strictly on the whole key (medicine_id), eliminating partial and transitive dependencies. The batch entity is isolated into a 1:N relationship with its own surrogate key (batch_id), preventing update anomalies when stock or expiry dates vary across shipments.

2. PL/pgSQL FEFO Engine Procedure: sp_dispense_medicine_fefo()

Allocates inventory using a PostgreSQL cursor ordered strictly by expiry_date ASC. Uses SELECT ... FOR UPDATE row-level locks on the batch table to eliminate race conditions (lost updates) when concurrent cashiers dispense from the same batch.

3. Database Triggers Patient Safety & Stock Ledger Integrity

trg_prevent_expired_dispense executes BEFORE INSERT on sales order items, throwing an explicit database exception (SQLSTATE '20001') if expiry_date < CURRENT_DATE. trg_auto_deduct_batch_stock executes AFTER INSERT to automatically decrement batch quantity and insert an immutable audit record into inventory_ledger.

4. Indexing & Optimization Partial Composite Index: idx_batch_fefo_active

Created as: CREATE INDEX idx_batch_fefo_active ON batch (medicine_id, expiry_date) WHERE quantity_available > 0 AND status IN ('ACTIVE', 'NEAR_EXPIRY');. Reduces FEFO lookup complexity from full table scan O(N) to targeted index scan O(log K).

5. Analytics & Views Materialized View: mv_monthly_pharmacy_financials

Caches multi-table financial aggregates (Gross Sales, COGS, Expiry Losses, Net Margins). Can be refreshed without locking queries using REFRESH MATERIALIZED VIEW CONCURRENTLY via its unique index on financial_month.
